# Module Spec: orchestrator.py

## 1. Module Overview
- **Name / ID:** `orchestrator`
- **Purpose:** Coordinates execution of all pipeline modules, handles logging, error handling, and pushes logs/config updates to GitHub.
- **Author / Date:** Paul – 21 Jan 2026

## 2. Upstream Dependencies
- GitHub Actions environment (`pipeline.yml`)
- Local filesystem access
- Python runtime with subprocess execution

## 3. Downstream Dependencies
Modules executed via `run_module()`:
- `modules/1.file_retrieval.py`
- `modules/2.transform_data.py`
- `modules/3.api_integration.py`
- `modules/4.data_quality.py`
- `modules/5.data_update.py`
- `modules/99.retention_policy.py`

## 4. Inputs / Sources
- Environment variables:
  - `GITHUB_TOKEN` → authentication for GitHub push
  - `GITHUB_REPOSITORY` → repository path
- `config.json` → loaded at runtime and updated during execution
- Runtime-generated timestamp (`datetime.now()`)

## 5. Outputs
- Timestamped workflow log file:
  - `data and logs/workflow_YYYYMMDD_HHhMM.log`
- Updated `config.json` with:
  - `last_run_date`
- Git commits pushed to repository:
  - log file
  - config file

## 6. Logic / Steps

### Initialization
1. Create folder `data and logs` if missing
2. Generate timestamp (`datetimestamp`)
3. Configure logging:
   - File-based log output
   - Format includes timestamp, severity, and module label `"Orchestrator"`

### Execution Flow
4. Load `config.json`
5. Execute modules sequentially using `run_module()`:
   - `1.file_retrieval.py`
   - `2.transform_data.py`
   - `3.api_integration.py`
   - `4.data_quality.py`
   - `5.data_update.py`
   - `99.retention_policy.py`

Each module execution:
- Logs start and end of execution
- Prints start message to stdout
- Runs as subprocess with:
  - `python <module_path> --log-file <log_file>`
  - timeout = 60 seconds
- Handles return codes:
  - `0` → success
  - `10` → skip (conditions not met, logged and ignored)
  - any other non-zero → failure

### Finalization
6. After modules complete:
- Reload `config.json`
- Update:
  - `config["last_run_date"] = datetimestamp`
- Call `save_log_and_config()`

## 7. Conditional Checks
- Return code `10`:
  - treated as **soft skip**
  - logged as INFO
  - pipeline continues

- Return code `!= 0 and != 10`:
  - treated as **failure**
  - logs stderr output
  - pushes log file immediately
  - exits process (`sys.exit(1)`)

## 8. Error Handling & Logging
- Uses Python `logging` module with file output
- Logger name: `"log_dog"`
- All subprocess execution wrapped in `try/except`
- On exception:
  - full stack trace logged via `logger.exception`
  - log file pushed to GitHub
  - exception re-raised

- Logging levels used:
  - `INFO` → normal flow, start/end/module status
  - `ERROR` → subprocess failures
  - `EXCEPTION` → unexpected runtime errors

## 9. Helper Functions

### `run_module(module_path)`
- Runs a Python script as subprocess
- Passes `--log-file` argument
- Captures stdout/stderr
- Handles:
  - success
  - skip (return code 10)
  - failure (non-zero exit)

### `push_file_to_repo(file_path, commit_message)`
- Stages file using `git add`
- Commits changes (non-fatal if nothing changed)
- Pushes directly to `main` branch
- Uses:
  - `GITHUB_TOKEN`
  - `GITHUB_REPOSITORY`
- Sets Git identity:
  - `github-actions`

### `save_log_and_config()`
- Logs orchestrator completion
- Pushes log file to GitHub
- Writes updated `config.json`
- Pushes updated config file to GitHub

**Runtime dependencies:**
- `config`
- `config_file`
- `log_file`
- `datetimestamp`
