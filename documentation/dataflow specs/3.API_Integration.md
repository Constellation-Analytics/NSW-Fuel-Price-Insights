# Module Spec: 3.station_dictionary_sync.py
## 1. Module Overview
- **Name / ID:** `3.station_dictionary_sync.py` (script label: `3.API_Integration.py`)
- **Purpose:**
  Loads FuelCheck station reference data from API and compares it with the PostgreSQL station dictionary.  
  Detects new, deleted, and updated stations and writes results to staging tables for downstream processing.
- **Author / Date:** Paul – 21 Feb 2026



## 2. Upstream Dependencies
- Orchestrator module (`orchestrator.py`)
- PostgreSQL database (via `dim_fuel_stations`)
- Environment variables (API + DB credentials)



## 3. Downstream Dependencies
- `4.data_quality.py`
- `5.data_update.py`



## 4. Inputs / Sources

### Environment variables / secrets
- `DB_CONNECTION_STRING` → PostgreSQL connection (NEON)
- `API_KEY` → FuelCheck API key
- `API_SECRET` → (declared but not used in this module)
- `API_AUTHORISATION_HEADER` → OAuth authorization header
- `GITHUB_TOKEN` → GitHub push
- `GITHUB_REPOSITORY` → repository path



### Config file (`config.json`)
- `latest_file`
- `last_API_call_update`



### External API endpoints
- OAuth token:
  - `https://api.onegov.nsw.gov.au/oauth/client_credential/accesstoken`
- Station reference data:
  - `https://api.onegov.nsw.gov.au/FuelCheckRefData/v2/fuel/lovs`



### Database source
- `dim_fuel_stations`



## 5. Outputs

### Config updates
- `last_API_call` → timestamp of API run
- `last_API_call_update` → set to `latest_file`

### Database outputs (staging tables)
- `stg_inactive_stations`
- `stg_new_stations`
- `stg_updated_stations`

### Logging
- Written to orchestrator log file via shared logger



## 6. Logic / Steps

### Initialization
1. Parse `--log-file`
2. Initialise logging using orchestrator log file
3. Load `config.json`
4. Create PostgreSQL engine using `DB_CONNECTION_STRING`
5. Generate runtime values:
   - `latest_file`
   - `current_monthyear`
   - UTC timestamp (`now`)
   - UUID transaction id



### API authentication
6. Request OAuth access token via `create_access_token()`
   - Uses client credentials grant
   - Returns bearer token



### API data extraction
7. Call station reference API via `api_data()`
8. Validate responses:
   - If token is `None` → exit with error
   - If data is `None` → exit with error



### Data transformation
9. Normalize station JSON into DataFrame
10. Clean and structure address fields:
   - Extract `street`
   - Extract `town`
   - Extract `postcode`
11. Standardise text:
   - title case for street/town
   - strip whitespace for name/address
12. Add timestamp column (`last_update`)
13. Select required columns and rename:
   - `code` → `stationid`
   - `location.latitude` → `latitude`
   - `location.longitude` → `longitude`
14. Cast `stationid` to string



### Database comparison
15. Load station dictionary from `dim_fuel_stations`
16. Compute differences:

- **Deleted stations**
  - in DB but not in API

- **New stations**
  - in API but not in DB

- **Updated stations**
  - matching `stationid`
  - where `name` or `address` differs



### Staging insert
17. Insert results into PostgreSQL staging tables:
- `stg_inactive_stations`
- `stg_new_stations`
- `stg_updated_stations`



### Finalization
18. Update config:
- `last_API_call = datetimestamp`
- `last_API_call_update = latest_file`

19. Save config file (writes + pushes to GitHub)



## 7. Conditional Checks

- If API token generation fails → `sys.exit(1)`
- If API data retrieval fails → `sys.exit(1)`
- If database insert fails → `sys.exit(1)`
- If config indicates file already processed:
  - `latest_file == last_API_call_update` → `sys.exit(10)` (skip)


## 8. Error Handling & Logging

- Logging:
  - Shared orchestrator log file
  - Module label: `"Module 3"`

- API failures:
  - logged explicitly
  - terminate execution (`sys.exit(1)`)

- Database failures:
  - caught in `try/except`
  - logged with stack trace
  - fail workflow

- No silent failures except controlled skip (`sys.exit(10)`)
