# Module Spec: 5.data_update.py

## 1. Module Overview  
- **Name / ID:** `5.data_update.py`  
- **Purpose:**  
  Executes SQL stored procedures to promote validated data from staging into production tables.  
  Applies updates to station and pricing data, logs execution results, and conditionally finalises the pipeline by updating configuration and truncating staging tables.  
- **Author / Date:** Paul – 26 Feb 2026  


## 2. Upstream Dependencies  
- Orchestrator module (`orchestrator.py`)  
- Data quality module (`4.data_quality.py`)  
- Database staging tables from (`3.API_Integration.py`)  

- Environment variable:  
  - `DB_CONNECTION_STRING`  

- Stored Procedures:  
  - `update_fuel_stations_active()`  
  - `update_fact_fuel()`  
  - `update_fuel_stations_inactive()`  
  - `truncate_stg_tables()`  


## 3. Downstream Dependencies  
- Reporting layer (Power BI / Analytics consumption)  
- Production database tables:  
  - `fact_fuel_prices`  
  - `dim_fuel_stations`  


## 4. Inputs / Sources  

### Environment Variables  
- `DB_CONNECTION_STRING` – PostgreSQL (NEON) connection  


### Config file (`config.json`)  
- `latest_file`  
- `last_data_update`  


### Database Tables  
- `stg_fuel_price`  
- `stg_new_stations`  
- `stg_updated_stations`  
- `dim_fuel_stations`  
- `dq_issues`  


### Stored Procedures  
- `update_fuel_stations_active()`  
- `update_fact_fuel()`  
- `update_fuel_stations_inactive()`  
- `truncate_stg_tables()`  


## 5. Outputs  

### Database Tables  
- `fact_fuel_prices` → updated pricing data  
- `dim_fuel_stations` → updated station data  
- `sys_run_log` → procedure execution logs  


### Config Updates  
- `last_data_update` → set to `latest_file` when updates occur  


### Logging  
- Written to orchestrator log file  
- Includes:
  - procedure execution summaries  
  - row counts per procedure  


## 6. Logic / Processing Overview  

### Initialization
1. Parse `--log-file`
2. Initialise logging
3. Load `config.json`
4. Create database engine


### Skip condition (idempotency)
5. Exit with `sys.exit(10)` if:
- `latest_file == last_data_update`


### Data update execution

6. Execute stored procedures sequentially:
- `update_fuel_stations_active()`
- `update_fact_fuel()`
- `update_fuel_stations_inactive()`

7. For each procedure:
- Execute via `run_stored_procedure()`
- Read results from `sys_run_log`
- Log:
  - procedure name
  - description
  - rows affected


### Post-processing

8. Capture:
- `price_updates = rows affected from update_fact_fuel()`

9. Log total updates:
- `"Total price updates = X rows"`


### Conditional finalisation

10. If `price_updates > 0`:
- Update config:
  - `last_data_update = latest_file`
- Execute:
  - `truncate_stg_tables()`
- Save and push updated config


## 7. Conditional Checks  

### Skip condition
- `latest_file == last_data_update` → skip module (`sys.exit(10)`)


### Update condition
- Config + staging cleanup only triggered if:
  - `price_updates > 0`


### Failure conditions
- DB connection failure → exception
- Stored procedure failure → exception
- Config save failure → logged exception


## 8. Error Handling & Logging  

- Uses shared orchestrator log file  
- Logs:
  - procedure execution results (INFO level)
  - total updates

- Stored procedures executed inside:
  - transactional context (`engine.begin()`)

- Fail behaviour:
  - exceptions propagate to orchestrator

- Skip behaviour:
  - controlled via `sys.exit(10)`


## 9. Helper Functions

### `run_stored_procedure(conn, logger, procedure)`
- Executes PostgreSQL stored procedure:
  - `CALL <procedure>()`
- Reads execution results from `sys_run_log`
- Logs each entry:
  - procedure name
  - description
  - rows affected
- Aggregates total rows affected
- Returns:
  - total number of affected rows


### `push_file_to_repo(file_path, commit_message)`
- Stages file using `git add`
- Commits changes (non-fatal if nothing changed)
- Pushes directly to `main` branch
- Uses:
  - `GITHUB_TOKEN`
  - `GITHUB_REPOSITORY`
- Sets Git identity:
  - `github-actions`
- Raises exception if git command fails


### `save_config()`
- Writes updated `config.json`
- Logs successful update
- Pushes config file to GitHub via `push_file_to_repo()`
