# Module Spec: 4.data_quality.py

## 1. Module Overview
- **Name / ID:** `4.data_quality.py`
- **Purpose:**
  Executes data quality checks and automated fixes on FuelCheck data using PostgreSQL stored procedures.  
  Logs results and triggers autofix routines when issues are detected.
- **Author / Date:** Paul – 21 Feb 2026

## 2. Upstream Dependencies
- Orchestrator module (`orchestrator.py`)
- PostgreSQL database
- Environment variable:
  - `DB_CONNECTION_STRING`
- Data dependency:
  - Outputs from `3.API_Integration.py`

## 3. Downstream Dependencies
- `5.data_update.py`

## 4. Inputs / Sources

### Environment variables
- `DB_CONNECTION_STRING` → PostgreSQL connection string

### Config file (`config.json`)
- `latest_file`
- `last_data_update`

### Database stored procedures
- `check_data_quality()`
- `update_data_quality_autofix()`
- `check_data_quality()` [view specs](/documentation/SQL/stored%20procedures/check_data_quality.md)


### Database log table
- `sys_run_log`

## 5. Outputs

### Database outputs
- `dq_issues` (populated via stored procedures)
- `sys_run_log` (execution metadata)

### Logging
- Written to orchestrator-provided log file
- Includes:
  - procedure execution status
  - row counts
  - descriptive messages

## 6. Logic / Steps

### Initialization
1. Parse `--log-file`
2. Initialise logging
3. Load `config.json`
4. Create PostgreSQL engine using `DB_CONNECTION_STRING`

### Skip condition (idempotency)
5. Exit with `sys.exit(10)` if:
   - `latest_file == last_data_update`

### Data quality execution flow

6. Run stored procedure:
- `check_data_quality()`

7. Capture execution metadata from `sys_run_log`

8. Log each record as WARNING:
- `procedure_name | description | rows_affected`

9. Sum total `rows_affected`

### Autofix flow

10. If `rows_affected > 0`:
- run `update_data_quality_autofix()`
- re-run `check_data_quality()` to validate fixes

## 7. Conditional Checks

### Skip
- If already processed:
  - `sys.exit(10)`

### Failure
- DB connection failure → exception raised
- Stored procedure failure → pipeline fails
- Logging query failure → pipeline fails

## 8. Error Handling & Logging

- Uses shared orchestrator log file
- Logs:
  - stored procedure execution
  - defect summaries
  - autofix actions

- Execution runs inside:
  - transactional context (`engine.begin()`)

- Fail behavior:
  - unhandled exceptions propagate to orchestrator

- Skip behavior:
  - `sys.exit(10)` for idempotent execution

## 9. Helper Functions

### `run_stored_procedure(conn, logger, procedure)`
- Executes PostgreSQL stored procedure:
  - `CALL <procedure>()`
- Reads execution results from `sys_run_log`
- Logs each entry:
  - procedure name
  - description
  - rows affected
- Aggregates total rows affected
- Returns:
  - total number of affected rows
- Used to control autofix logic

**Runtime dependencies:**
- `sys_run_log` table must be populated by stored procedures
