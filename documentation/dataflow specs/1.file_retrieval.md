# Module Spec: 1.file_retrieval.py

## 1. Module Overview
- **Name / ID:** `1.file_retrieval.py`
- **Purpose:** Retrieves the latest monthly Fuel Check dataset from NSW Government, converts it to CSV, commits it to GitHub, and updates runtime configuration (`config.json`).
- **Author / Date:** Paul – 21 Jan 2026

## 2. Upstream Dependencies
- Orchestrator module (`orchestrator.py`)

## 3. Downstream Dependencies
- `2.transform_data.py`
- `3.api_integration.py`
- `4.data_quality.py`
- `5.data_update.py`

## 4. Inputs / Sources

### Environment variables
- `GITHUB_TOKEN` → GitHub authentication
- `GITHUB_REPOSITORY` → repository path

### Web source
- NSW Fuel Check dataset page  
  https://data.nsw.gov.au/data/dataset/fuel-check

### Config file (`config.json`)
- `next_file_date`
- `latest_file`
- `last_transformation`

### Command-line arguments
- `--log-file` (provided by orchestrator)

### System time
- Used for:
  - idempotency checks
  - monthly filtering
  - file naming

## 5. Outputs

- Monthly fuel dataset saved as CSV:
  - Path: `data and logs/fuelcheck_<mon><year>.csv`

- Updated `config.json`:
  - `latest_file`
  - `next_file_date`

- Git commits:
  - CSV data file
  - updated config file

- Logs written to orchestrator-provided log file

## 6. Logic / Steps

### Initialization
1. Parse `--log-file` argument
2. Initialise logging using shared log file
3. Load `config.json`
4. Compute:
   - `latest_file`
   - `nextfile` (next expected dataset)
   - parsed datetime objects for filtering
   - `current_monthyear`

### Early exit conditions (idempotency gates)

5. Exit with `sys.exit(10)` if:
   - `current_monthyear == nextfile`
     → already processed for this cycle
   - no matching dataset link found on webpage
   - `config["latest_file"] != config["last_transformation"]`
     → transformation pipeline not yet completed

### Data retrieval

6. Request Fuel Check webpage using `requests`
7. Parse HTML using `BeautifulSoup`
8. Filter links:
   - must end in `.csv` or `.xlsx`
   - must contain:
     - next month name (lowercase)
     - next year

### Download + processing

9. Download first matching dataset link
10. Load into pandas:
   - `.xlsx` → `pd.read_excel(BytesIO())`
   - `.csv` → `pd.read_csv(StringIO())`
11. Convert to CSV and save:
   - `data and logs/fuelcheck_<mon><year>.csv`

### Persistence

12. Push CSV file to GitHub
13. Update config:
   - `latest_file = nextfile`
   - `next_file_date = next month (computed via relativedelta)`
14. Save and push updated config file

## 7. Conditional Checks

### Skip conditions (non-fatal, exit code 10)
- Dataset already processed for current month
- Dataset not yet available on website
- Transformation not yet completed (`last_transformation` mismatch)

### Supported formats
- `.csv`
- `.xlsx`

## 8. Error Handling & Logging

- Uses shared orchestrator log file
- Logs:
  - connection attempts
  - filtering decisions
  - download status
  - transformation steps

- Git operations:
  - wrapped in `try/except`
  - exceptions logged with stack trace

- Non-critical exits:
  - `sys.exit(10)` → safe skip

- Critical failures:
  - allow exception propagation (unhandled → orchestrator stops pipeline)

## 9. Helper Functions

### `push_file_to_repo(file_path, commit_message)`
- Adds file via git
- Commits changes (no failure if nothing changed)
- Pushes to `main`
- Uses:
  - `GITHUB_TOKEN`
  - `GITHUB_REPOSITORY`

### `save_config()`
- Writes `config.json`
- Logs update
- Pushes config file to GitHub
